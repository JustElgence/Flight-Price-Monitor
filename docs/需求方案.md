# 机票价格监控网页 — 需求方案 v0.1

> 日期：2026-10-17
> 部署目标服务器：14.103.98.164（Ubuntu 24.04 LTS / 4C4G / 40G 盘 / 已装 Docker 29.1、Python 3.12、Nginx）

---

## 1. 项目概述

一个自用的机票价格监控网站：输入**出发地 + 目的地（+ 日期）**，系统定期抓取价格并绘制**历史价格曲线**；当价格跌破用户设定的**阈值**时，通过 **IM 即时通讯**推送告警。

核心价值：把"每天手动去 APP 刷票价"变成"设置一次，降价自动通知"。

## 2. 功能需求

### 2.1 P0（首期必须）

| 模块 | 功能点 | 说明 |
|------|--------|------|
| 航线查询 | 出发地/目的地选择 | 支持中文城市名/机场三字码（如 PEK→SHA），自动补全 |
| | 单程/往返、日期（或日期区间） | 首期先做单程+单日 |
| 价格抓取 | 定时抓取报价 | 默认每 30~60 分钟一轮，可配置；抓取失败自动重试 |
| 历史曲线 | 最低价趋势图 | 按航线展示"每日/每时段最低价"折线图（ECharts） |
| | 各航司/航班对比 | 同一时刻在售报价列表（航司、航班号、起飞时间、价格） |
| 阈值告警 | 设置价格阈值 | 每条监控航线一个阈值；低于阈值触发通知 |
| | IM 通知 | 对接 webhook 类 IM：企业微信机器人 / 钉钉机器人 / Telegram Bot / Bark（任选，首期做一个，接口抽象成通用通知器） |
| 监控管理 | 增删启停监控任务 | 管理页：航线列表、抓取频率、阈值、通知渠道 |

### 2.2 P1（二期增强）

- 多日期对比视图（日历热力图：哪天飞最便宜）
- 价格订阅分享：微信扫码/链接直达
- 转机/联程查询
- 多用户（登录注册），首期为单用户免登录或简单密码

### 2.3 非功能需求

- 抓取频率受控，遵守目标站点 robots 与访问频率礼仪，避免封 IP
- 告警去重：同一条航线同一价格不重复轰炸（冷却期默认 6 小时）
- 数据留存 ≥ 180 天；抓取失败不影响页面展示（显示最后成功数据）
- 服务异常自恢复：Docker `restart: unless-stopped`

## 3. 数据源：实测结论（2026-10-17 已验证）✅

### 3.1 实测过程

| 尝试 | 结果 |
|------|------|
| 携程 lowestPrice 接口（纯 HTTP） | ❌ whaleguard 风控拦截（补 Cookie、改 Referer 均无效） |
| 携程列表页（无头/有头 Playwright） | ❌ whaleguard 均拦截，需要真实浏览器指纹 |
| 去哪儿 touch 接口（纯 HTTP） | ❌ 接口 404（已下线） |
| 去哪儿 m.flight.qunar.com 列表页 | ❌ 强制登录 |
| **同程 ly.com PC 列表页（无头 Playwright）** | ✅ **匿名可访问，页面直接渲染每日最低价日历** |

### 3.2 已验证的数据源：同程 PC 机票列表页

- URL：`https://www.ly.com/flights/itinerary/oneway/{dep}-{arr}?date={YYYY-MM-DD}`（dep/arr 用三字码）
- 数据：页面 SSR 渲染出**未来约 75~108 天的每日最低价日历**，DOM 文本可用正则
  `(\d{2}-\d{2}) 周X ¥(\d+)` 直接提取
- 已验证航线：SHA→BJS（75 天）、CAN→SYX（108 天）
- 实现脚本：`scripts/fetch_ly_price.py`（Playwright 无头 Chromium，单次约 15 秒）

### 3.3 定案方案（零成本）

- **主数据源**：同程列表页每日最低价日历（免费，低频 2~3 次/天完全无压力）
- **增强项（二期）**：进入具体日期再抓航司/航班号/起飞时间明细
- **兜底**：若同程页面改版 → 启用付费聚合接口（几厘/次），适配器隔离，切换零成本
- 注意：低价日历为"当日实时最低价"，历史曲线由我们**自己落库累积**（这正是本项目的核心价值，第三方没有现成的历史数据）

## 4. 系统架构

```
┌─────────────┐     ┌──────────────────────────────────────────┐
│   浏览器     │────▶│  Nginx (静态页面 + 反向代理 /api)          │
└─────────────┘     └───────────────┬──────────────────────────┘
                                    ▼
                    ┌───────────────────────────────┐
                    │  FastAPI 后端 (Docker 容器)     │
                    │  ├─ REST API（航线/曲线/阈值）  │
                    │  └─ APScheduler 定时任务        │
                    │      ├─ 抓取器 (数据源适配器)   │──▶ 机票数据 API
                    │      └─ 告警器 (阈值判断+去重)  │──▶ IM Webhook
                    └───────────────┬───────────────┘
                                    ▼
                          SQLite（价格历史/任务配置）
```

## 5. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 后端 | Python 3.12 + FastAPI + httpx | 服务器已装 Python；异步抓取并发友好 |
| 定时任务 | APScheduler（进程内） | 单用户场景，无需引入 Celery/Redis，降低内存占用 |
| 数据库 | SQLite（WAL 模式） | 数据量小（10 条航线×1 年 ≈ 百万行内），零运维 |
| 前端 | Vue 3 + Vite + ECharts + Element Plus | 曲线图成熟方案，打包后由 Nginx 托管 |
| 通知 | 通用 Notifier 抽象：`{channel: wecom|dingtalk|telegram|bark, webhook_url}` | 首期实现 1 个（建议企业微信机器人），其余按需加 |
| 部署 | Docker Compose + Nginx | 服务器已有 Docker 与 Nginx，两个容器即可（backend + 前端静态） |

## 6. 数据库设计（简版）

```sql
-- 监控任务
CREATE TABLE monitor_task (
  id INTEGER PRIMARY KEY,
  dep_code TEXT, arr_code TEXT,          -- 三字码，如 PEK/SHA
  date TEXT,                              -- 出行日期 YYYY-MM-DD
  threshold REAL,                         -- 告警阈值（元）
  interval_min INTEGER DEFAULT 60,       -- 抓取间隔
  enabled INTEGER DEFAULT 1,
  created_at TEXT
);

-- 价格历史（每次抓取的最低价 + 详情快照）
CREATE TABLE price_record (
  id INTEGER PRIMARY KEY,
  task_id INTEGER REFERENCES monitor_task(id),
  captured_at TEXT,                       -- 抓取时间
  min_price REAL,                         -- 本轮最低价
  airline TEXT, flight_no TEXT, dep_time TEXT
);
CREATE INDEX idx_record_task_time ON price_record(task_id, captured_at);

-- 告警记录（用于去重与展示）
CREATE TABLE alert_log (
  id INTEGER PRIMARY KEY,
  task_id INTEGER, price REAL, notified_at TEXT, channel TEXT
);
```

## 7. 核心 API 草案

| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | `/api/tasks` | 监控任务列表（含最新价格、是否触发中） |
| POST | `/api/tasks` | 新建监控（出发地、目的地、日期、阈值、频率） |
| PATCH| `/api/tasks/{id}` | 修改阈值/启停 |
| DELETE| `/api/tasks/{id}` | 删除 |
| GET  | `/api/tasks/{id}/history?days=30` | 历史最低价序列（喂给 ECharts） |
| GET  | `/api/tasks/{id}/latest` | 最新一轮各航班报价明细 |
| POST | `/api/settings/notify` | 配置 IM webhook（含"发送测试消息"按钮） |

## 8. 告警流程

```
定时器触发 → 调数据源 API → 解析最低价 → 写入 price_record
   → 若 min_price ≤ threshold
      → 查 alert_log：该任务 6 小时内已通知过？ → 是：跳过
      → 否：组装消息（航线/日期/当前价/较昨日降幅/直达链接）→ 发 IM webhook → 记录 alert_log
```

通知消息示例（企业微信 markdown）：
> ✈️ **降价提醒** PEK→SHA 2026-11-20
> 当前最低 **¥420**（东航 MU5101，08:00 起飞）
> 已低于你的阈值 ¥500，较 7 天前低 23%
> [点我查看](https://监控站地址/task/1)

## 9. 部署方案（14.103.98.164）

- 目录：`/opt/flymon/`，Git 仓库即本工作区，`git pull` + `docker compose up -d` 发布
- 容器：`flymon-backend`（FastAPI+调度）、前端 `dist` 静态文件由宿主 Nginx 托管
- Nginx：新增 `flymon.<可选域名或 IP:端口>` server 块，`/api` 反代到 backend 容器
- 内存预估：backend ≈ 150MB，当前可用 1.3G，足够
- 日志：Docker json-file 轮转（max-size 10m × 3），SQLite 每日自动备份到 `/opt/flymon/backup/`

## 11. 风险与说明

1. **数据源成本/稳定性**是首要风险 → M1 先行验证，适配器隔离，随时可换源
2. 爬 OTA 方案有风控与合规风险，仅作技术备选，不作为默认路径
3. 单用户自用，暂不做账号体系；若需公网访问，建议 Nginx 层加 Basic Auth
4. 本方案不含出票、支付等交易功能，仅做**价格监控与提醒**
